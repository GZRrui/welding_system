交付验收以新 Linux 主机为准。运维按文档启动服务，导入已有历史，使用发布模型完成预测和推荐，并从加密异机备份恢复后重复核对。

| 1 | 单管理员、会话、CSRF、操作审计 | 业务接口拒绝匿名请求，退出和改密立即注销相应会话 |
| 2 | 显式迁移、PostgreSQL、历史导入 | 空库安装和已有 SQLite 升级通过；核对历史数量、模型与容差版本、复核记录 |

## SQLite 历史导入

停用旧 Windows 应用的写入并保留原目录和导出文件。向全新迁移完成、尚未启动 API 的 PostgreSQL 数据库导入。迁移和导入使用维护账号的 `DATABASE_URL`。

```sh
python -m alembic upgrade head
python -m app.import_history --source /data/legacy/system.db --backup /data/legacy/pre-import.db
```

导入前通过 SQLite 在线备份接口生成独立快照，检查完整性与外键。导入单事务内按外键顺序写入并逐行校验 JSON、版本引用、复核状态和备注。目标历史表已有记录时命令终止，源库和备份保持可用于重试。复制对应任务 ID 的旧导出目录到生产导出卷，再启动 API。抽查有预测区间和有复核备注的历史详情及导出。

## 初始化和重置管理员

进入 `backend`，使用应用依赖所在的解释器运行：

```sh
python -m alembic upgrade head
python -m app.auth
```

交互输入两次密码。该命令初始化固定账户 `admin`，重置时撤销所有会话。密码至少 12 个字符。浏览器内可改密，改密后所有浏览器需要重新登录。

生产默认使用 Secure、HttpOnly、SameSite=Strict Cookie。Windows 开发脚本在环回 HTTP 环境关闭 Secure。生产页面和 API 使用同一 HTTPS 域名。Cookie 只保存随机标识，数据库保存其摘要。修改请求需带当前会话返回的 `X-CSRF-Token`。

`SESSION_IDLE_SECONDS` 和 `SESSION_MAX_SECONDS` 缺省为 1800 与 28800。`LOGIN_FAILURE_LIMIT` 和 `LOGIN_WINDOW_SECONDS` 缺省为固定账户每 60 秒 5 次失败。多台客户端共享该限流。审计保存在 `audit_events`，包含登录结果、密码操作、退出、预测记录保存、推荐任务创建、复核修改和导出。
